SimpMusic's software grant covers its licensed code. The release needs separate evidence for media and service access. Leave the approval gate disabled until the maintainer can document authorization or has approved changes to the affected features.


## Release-specific evidence and owner decisions

- `YtApi.kt` and `Streams.kt` implement YouTube and YouTube Music access and extracted playback. The authorization must cover the actual search and playback interfaces, background audio, any transient cache, and thumbnail or album-art display. A music subscription or the GPL grant alone provides no evidence for those uses. If authorization cannot be produced, the option for approval is to replace extracted playback with an official service handoff or approved visible player and retain background playback for user-owned or licensed audio. [YouTube Terms](https://www.youtube.com/t/terms) · [YouTube API policies](https://developers.google.com/youtube/terms/developer-policies)
- Confirm that the selected lyrics services and rights holders grant the app its display, cache and sharing uses. LRCLIB's API is accessible and lyrics.ovh publishes service code under MIT. lyrics.ovh lists several upstream lyrics sources. Those facts document API access and the software license. The proposed fallback is licensed lyrics or user-supplied lyrics if rights for a provider are unavailable. [LRCLIB API](https://lrclib.net/docs) · [lyrics.ovh API and source list](https://github.com/NTag/lyrics.ovh)
- Document permission for the bundled developer portrait and launcher logo. Supply the logo generator and terms applicable when generated, the status of any supplied artwork, and the photographer or other rights holder's permission for the portrait. For artwork and album covers delivered through services, record the source's display and cache permissions. No asset substitutions were made.
- For optional APIs in `RemoteMetadata.kt`, `LastFmScrobble.kt`, `AiTools.kt` and configurable community endpoints, record the enabled provider accounts and permitted uses, applicable attribution, and retention and privacy disclosures. MusicBrainz's licensing distinguishes its data sets, and its API documents rate limits. OpenAI and Gemini publish service/provider-specific data terms. Provide operator, retention and contact details for any backend the maintainer operates. [MusicBrainz data licenses](https://musicbrainz.org/doc/MusicBrainz_Database/License) · [MusicBrainz API rate limits](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting) · [OpenAI API data](https://platform.openai.com/docs/guides/your-data) · [Gemini API terms](https://ai.google.dev/gemini-api/terms)
- The original GANASUNO notes attribute API information to SimpMusic. `THIRD_PARTY.md`, the README and bundled notices retain that credit. Identify any code or assets actually copied from SimpMusic or other projects, with upstream file, revision, original notices and modifications, so the corresponding attribution can be released accurately.
